# LAND INTELLIGENCE

**Document + Parcel Verification Platform**

This project extends the existing FastAPI document-screening application into a property-intelligence workflow:

**Document → OCR → Structured Property Identity → Property Resolution → Parcel → Map → Comparison → Human Verification → Audit**

## Current data boundary

> **Demo / Synthetic Land Data**
>
> The current parcel dataset is synthetic/demo data. It is project-owned demonstration geometry and is **not** an official cadastral dataset, government record, legal opinion, or ownership determination.

No government portal is scraped. No government dataset is copied or redistributed. Government APIs and authorized cadastral providers are future integrations only.

## What is preserved

The existing FastAPI application remains the source of truth for authentication, roles, document upload, OCR, AI-assisted extraction, validation, comparisons, tasks, audit logging, and the admin assistant. The Land Intelligence layer is additive and imports the existing `server.app` rather than replacing those capabilities.

## New components

- `land_intelligence.py` — property/parcel schema, resolution, provenance, comparison, verification cases and safe GeoJSON import.
- `demo_land.py` — credential-free synthetic demo API; it contains no real land records.
- `land-intelligence.html` / `.css` / `.js` — original GIS investigation workspace.
- `main.py` — production ASGI entrypoint. It imports the existing `server.app` and registers Land Intelligence routes without replacing the original application.
- `site.py` — retained compatibility module; deployments use `main:app`.
- `tests/test_land_intelligence.py` — automated tests for the synthetic GIS/demo workflow.

## Property model

The canonical `properties` table supports:

`property_id`, `parcel_id`, `district`, `taluka`, `village`, `survey_number`, `gat_number`, `khasra_number`, `sub_division`, `parent_property_id`, `area`, `area_unit`, `geometry`, `centroid`, `latitude`, `longitude`, `crs`, `georeferenced`, `geometry_source`, `geometry_confidence`, `data_source`, `source_confidence`, timestamps.

Supporting tables:

- `property_documents` — explicit document-to-property links.
- `provenance` — field-level source and confidence.
- `property_timeline` — events actually generated by the system.
- `verification_cases` — human review cases and findings.
- `verification_tasks` — case tasks.

SQLite remains the zero-cost default; the existing PostgreSQL compatibility path is preserved.

## GIS architecture

Parcel geometry is GeoJSON and EPSG:4326 in the demo. Shapely is used for validation and neighbour geometry checks. The browser uses Leaflet, an open-source mapping library.

Base-map configuration is environment-driven:

- `MAP_TILE_URL`
- `MAP_ATTRIBUTION`
- `MAP_MAX_ZOOM` / `MAP_MIN_ZOOM` can be supplied to future UI/provider integrations.

The default demo uses OpenStreetMap-compatible tiles only as a visual enhancement and displays attribution. The application does **not** bulk-download tiles, mirror tiles, or depend on a commercial map SDK. If tiles fail, parcel data and property intelligence remain available.

## Routes

### UI

- `GET /land-intelligence` — GIS/property investigation workspace.
- `GET /land-intelligence.css` — explicit `text/css` asset route.
- `GET /land-intelligence.js` — explicit JavaScript asset route.

### Credential-free demo API

- `GET /api/demo-land/health`
- `GET /api/demo-land/dashboard`
- `GET /api/demo-land/geojson`
- `GET /api/demo-land/properties?q=...`
- `GET /api/demo-land/properties/{property_id}`
- `GET /api/demo-land/documents`
- `GET /api/demo-land/compare/{doc_id}/{property_id}`

### Administrator AI governance API

- `GET /api/admin/ai-approval/proposals` — administrator-only proposal queue.
- `GET /api/admin/ai-approval/proposals/{proposal_id}` — proposal details.
- `POST /api/admin/ai-approval/proposals/{proposal_id}/approve` — explicit administrator approval and one-time execution.
- `POST /api/admin/ai-approval/proposals/{proposal_id}/reject` — explicit administrator rejection.
- `GET /api/admin/ai-approval/proposals/{proposal_id}/events` — proposal governance history.

Consequential AI actions are never executed from model output or legacy action tokens. The server validates a registered action type, target, before-state and administrator role before execution, then records the decision and result in the audit trail.

### Authenticated production API

- `GET /api/land/properties` — filtered/paginated property search.
- `GET /api/land/properties/{property_id}` — property intelligence, linked documents, neighbours, provenance and timeline.
- `GET /api/land/geojson` — bounded parcel GeoJSON.
- `GET /api/land/resolve/document/{doc_id}` — resolve an existing uploaded document against controlled parcel data.
- `GET /api/land/compare/{doc_id}/{property_id}` — neutral document/parcel comparison.
- `GET /api/land/dashboard` — property intelligence metrics.
- `GET /api/land/cases` and `GET /api/land/cases/{case_id}` — verification cases.
- `POST /api/land/cases` — create a human verification case.
- `POST /api/land/import-geojson` — role-protected local GeoJSON import with size, feature-count and geometry validation.

A match is never forced. Resolution statuses are `MATCH`, `POSSIBLE MATCH`, `NO MATCH`, and `INSUFFICIENT DATA`.

## Document ↔ parcel comparison

The engine compares survey/Gat/Khasra identity, village, taluka, district, subdivision and area where available. Area difference uses a configurable tolerance (`LAND_AREA_TOLERANCE_HA`, default `0.05`). Results are neutral:

- `CONSISTENT`
- `REVIEW REQUIRED`
- `CONFLICT`
- `INSUFFICIENT EVIDENCE`

The system does not declare fraud, forgery, illegal ownership, or legally binding title decisions.

## Provenance and confidence

Important property fields retain source and confidence metadata. Example sources include `Synthetic GIS dataset`, `Uploaded document → OCR`, or future authorized imports. Confidence is an indication of system/data quality, not truth.

## Privacy and security boundary

Uploaded documents remain behind the existing authenticated document routes. Data officers retain their existing ownership restrictions. The new property API applies the same authenticated user context for uploaded-document resolution and comparisons. Demo endpoints expose only synthetic records.

Do not commit secrets, credentials, or real sensitive documents. Do not send uploaded documents to map providers. GeoJSON import is constrained to user-supplied datasets and records source/licensing metadata.

The existing AI pipeline treats OCR text as document data. AI is assistive only; human verification remains authoritative.

## Free/no-mandatory-paid-service architecture

Core storage, GIS computation, parcel resolution, comparisons, case records, audit trail and demo mode run locally with SQLite, Python and open-source libraries. AI is optional at the application level and remains a separate provider; the GIS/property core does not call a paid AI, geocoder, routing API, government API or commercial GIS service.

No credit card, subscription, paid map SDK, or automatically billable cloud resource is required by the application code.

## Demo mode

Start the server and open `/land-intelligence`. The **Open demo property** action loads `DEMO-103-A`, its neighbours, synthetic linked documents, provenance and a deliberate 0.09 ha area difference that produces `REVIEW REQUIRED`.

## Local run

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

For OCR, install Tesseract locally. Docker already installs the existing Tesseract language packs.

## Docker

```bash
docker build -t land-intelligence .
docker run --rm -p 10000:10000 land-intelligence
```

The container runs `main:app`, the verified ASGI entrypoint. `main.py` imports the existing `server.app` and registers the Land Intelligence routes.

## Authentication bootstrap

No production administrator password is stored in source. For a new deployment, set `ADMIN_INITIAL_PASSWORD` to a strong private value before the first startup. Set `JWT_SECRET` to a strong persistent secret for stable sessions across restarts. Existing runtime databases are intentionally not committed to Git.

## Testing

```bash
pytest -q
```

The tests cover credential-free demo health, synthetic GeoJSON, property search, explicit reverse document links, area-consistency review behaviour and missing-property handling. Existing application tests should continue to be run alongside these tests when present.

## Adding authorized GIS data later

Use `POST /api/land/import-geojson` with an authorized, appropriately licensed dataset. Preserve the source, license, confidence, CRS and georeferenced status. Never silently import government records and never treat an imported dataset as authoritative without an appropriate authorized source and review process.
